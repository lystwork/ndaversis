Задание: Ndaversis - Agentic Semantic Version Info System
Создайте систему автоматического управления семантическим версионированием и генерации README документации с использованием AI и агентного подхода к разработке

Блок 1: Инфраструктура
Требования:

Docker Compose с одним сервисом:
ndaversis — Python приложение с CLI и GUI
Поддержка работы как в контейнере, так и локально
Персистентное хранение состояния через volumes

Результат:

docker-compose up --build
Приложение запускается и готово к работе
GUI доступен на http://localhost:8080

Блок 2: Основные функции
Автоматический анализ кодовой базы
При запуске система сканирует весь репозиторий
Извлекает метрики: строки кода, комментарии, пробелы, табуляции
Анализирует структуру: классы, функции, импорты, docstrings
Определяет языки программирования и их распределение

Семантическое версионирование
Автоматическое определение типа версии (major/minor/patch)
Сравнение текущего и предыдущего состояния кода
Генерация детального changelog с метриками изменений
Сохранение истории версий в ndaversis_version_history.py

Генерация README
Динамическое создание всех секций README.md
Автоматическая генерация диаграмм в Mermaid синтаксисе
Создание карт проекта, модулей, зависимостей
Синхронизация документации с текущим состоянием кода

Блок 3: AI-интеграция (Multi-Provider с Fallback)
Требования:

Поддержка множественных AI провайдеров с автоматическим переключением
Основной провайдер: Gemini (по умолчанию gemini-2.0-flash)
Fallback цепочка: Groq → OpenRouter → Mistral → DeepSeek → Qwen → Llama
Глобальный rate limiter: максимум 4 запроса в минуту для всей системы
Настройка кастомной модели через *_MODEL и опционально *_API_BASE
Обработка ошибок "Insufficient Balance" с автоматическим переходом к следующему провайдеру

Логика:

Система всегда берет текущее состояние кода и анализирует его
Запрашивает AI для генерации:
  - Use Cases (сценарии использования)
  - User Stories (пользовательские истории)
  - FAQ (часто задаваемые вопросы)
  - Описание изменений и их практическое значение
  - Предложения по дальнейшему развитию
Если провайдер возвращает текст вместо JSON, система обрабатывает "сырой ответ" без ошибки
При отсутствии AI ключей система работает в offline режиме с синтезированным контентом

Пример конфигурации в config.json:

{
  "ai_providers": {
    "primary": "gemini",
    "fallback_chain": ["groq", "openrouter", "mistral", "deepseek", "qwen", "llama"],
    "rate_limit": {
      "max_requests": 4,
      "time_window_seconds": 60
    },
    "providers": {
      "gemini": {
        "model": "gemini-2.0-flash",
        "api_base": null
      },
      "groq": {
        "model": "mixtral-8x7b-32768",
        "api_base": null
      }
    }
  }
}

Современный графический интерфейс на базе Flet
Поддержка desktop и web режимов
Интуитивная навигация с вкладками

  - Кнопка "Update Version & README"
  - Отображение текущей версии

Вкладка "Metrics Dashboard":

  - Столбчатые диаграммы для сравнительного анализа

Блок 5: Своя фича - Repository Evaluation Metrics
Реализуйте систему комплексной оценки репозитория как продукта для стейкхолдеров

Что делает фича:

Анализирует репозиторий по 15 ключевым параметрам
Каждая метрика оценивается в процентах (0-100%)
Для каждой метрики генерируется краткое AI-резюме
Результаты визуализируются в GUI с графиками и диаграммами

Метрики оценки:

1. Оценка качества кода (Code Quality)
   - Покрытие docstrings
   - Использование type hints
   - Сложность кода (cyclomatic complexity)
   
2. Оценка размера кода (Code Size)
   - Количество строк кода
   - Распределение размеров модулей
   - Соотношение код/комментарии

3. Оценка безопасности (Security)
   - Отсутствие hardcoded секретов
   - Использование безопасных паттернов
   - Валидация входных данных

4. Оценка применимости (Applicability)
   - Широта use cases
   - Гибкость конфигурации
   - Целевая аудитория

5. Оценка платформенности (Platform Compatibility)
   - Кроссплатформенность
   - Зависимости от ОС
   - Портируемость

6. Оценка количества (Quantity)
   - Количество функций/классов
   - Объем функционала
   - Полнота API

7. Оценка быстродействия (Performance)
   - Алгоритмическая сложность
   - Отсутствие узких мест
   - Оптимизация ресурсов

8. Оценка удобства (Usability)
   - Ясность API
   - Качество документации
   - Наличие примеров

9. Оценка надежности (Reliability)
   - Обработка ошибок
   - Покрытие тестами
   - Устойчивость к сбоям

10. Оценка инновационности (Innovation)
    - Уникальные фичи
    - Современные практики
    - Новаторские решения

11. Оценка простоты (Simplicity)
    - Сложность кода
    - Ясность архитектуры
    - Минимализм дизайна

12. Оценка эстетичности (Aesthetics)
    - Стиль кода
    - Соглашения об именовании
    - Консистентность форматирования

13. Оценка длительности (Duration/Maintainability)
    - Долгосрочная поддерживаемость
    - Техдолг
    - Готовность к развитию

14. Оценка точности (Accuracy)
    - Корректность реализации
    - Соответствие спецификациям
    - Отсутствие багов

15. Оценка законченности (Completeness)
    - Полнота функционала
    - Количество TODO
    - Готовность к продакшену

Зачем это нужно:

Предоставляет объективную оценку качества репозитория
Помогает стейкхолдерам принимать решения
Выявляет слабые места для улучшения
Отслеживает прогресс развития проекта

Как использовать:

CLI: python ndaversis.py --metrics
GUI: вкладка "Metrics Dashboard" → кнопка "Calculate Metrics"
Результат сохраняется в ndaversis_metrics.json

Блок 8: Использование AI (обязательный раздел)
Какие AI-инструменты использовались:

Google Gemini API - основной провайдер для генерации контента
Groq, OpenRouter, Mistral, DeepSeek, Qwen, Llama - fallback провайдеры
Claude/ChatGPT - для разработки и отладки кода (опционально)

Для каких задач AI помог больше всего:

Генерация Use Cases и User Stories на основе анализа кода
Создание описаний изменений с практической ценностью
Синтез FAQ и How-To секций
Генерация резюме для метрик оценки репозитория
Предложения по дальнейшему развитию проекта

Где пришлось доработать сгенерированный код:

Точная настройка промптов для структурированного вывода
Обработка edge cases при парсинге AI ответов
Оптимизация rate limiting для избежания quota exhaustion
Интеграция fallback логики между провайдерами
Кастомизация GUI компонентов под специфику метрик

Примерная оценка: сколько времени сэкономил AI:

Разработка базовой структуры: ~8 часов
Генерация документации: ~12 часов
Создание тестов: ~6 часов
Отладка и рефакторинг: ~4 часа
Итого: ~30 часов сэкономлено
